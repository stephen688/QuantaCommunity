# demo0 后端接口思维导图（Canvas 正文）

## L1 系统总览
- 系统名：`demo0` 后端接口体系（仅统计 `src/main/java/com/quanta/demo0/controller` 的方法级接口）
- 接口总量：**68**（`@GetMapping/@PostMapping/@PutMapping/@DeleteMapping`）
- 主线能力：用户与身份、内容与互动、关系推荐、检索与 RAG、通知公共能力、平台治理审核
- 设计目标：可运维、可扩展、可观测，强调审核闭环、读写性能与安全合规

## L2 模块
- 用户账号与身份模块（14）
- 内容发布与互动模块（19）
- 关系链路与推荐模块（2）
- 检索与智能问答模块（6）
- 通知与公共能力模块（5）
- 平台治理与审核模块（22）

> 校验说明：按 controller 实际扫描，模块分布合计 68。原计划中的 14/14/2/6/5/27 与代码现状不一致，已按真实接口归属锁定。

## L3 子域能力
- 用户账号与身份：登录会话、资料维护、认证申请、个人内容视图、公开主页
- 内容发布与互动：内容生命周期、评论回复、回答采纳、点赞收藏、举报闭环
- 关系链路与推荐：关注关系维护、关注流时间线
- 检索与智能问答：关键词检索、历史管理、热门聚合、RAG 检索增强
- 通知与公共能力：通知中心、已读状态管理、文件上传
- 平台治理与审核：内容/评论/回答治理、举报处置、用户封禁、身份审核、AI 审核记录

## L4-L5 接口树（含流程与亮点）

### 模块一：用户账号与身份（14）

- `[POST] /user/login`（微信登录）
  - 流程：接收登录凭证 -> 服务层换取用户身份 -> 生成 JWT 并写入 Redis -> 返回 token 与用户信息
  - 亮点：Redis 会话 TTL 控制；封禁状态前置拦截，避免已封禁账号继续会话

- `[GET] /user/info`（查询当前用户信息）
  - 流程：读取上下文 userId -> 查询用户资料 -> 返回回显
  - 亮点：轻量读接口；上下文解耦令牌解析与业务查询

- `[PUT] /user/info/update`（更新用户信息）
  - 流程：接收资料 DTO -> 参数校验 -> 持久化更新 -> 返回成功
  - 亮点：写操作聚合入口；便于后续扩展字段级审计

- `[POST] /user/auth/add`（提交身份认证）
  - 流程：接收认证信息 -> 创建认证记录 -> 返回认证对象
  - 亮点：认证数据独立建模；可衔接审核状态机

- `[GET] /user/auth/status`（查询认证状态）
  - 流程：按当前用户查询认证状态 -> 组装状态 VO -> 返回
  - 亮点：前后端状态解耦；支持认证流程可视化

- `[GET] /user/auth/detail`（查询认证详情）
  - 流程：按当前用户读取认证详情 -> 返回明细
  - 亮点：详情与状态分离；降低频繁列表查询成本

- `[GET] /user/content/my/list`（我的发布）
  - 流程：接收分页与状态 -> 按 userId 查询 -> 返回分页结果
  - 亮点：支持审核状态筛选；便于“待审/通过/驳回”运营视图

- `[GET] /user/content/my/liked`（我的点赞）
  - 流程：接收分页参数 -> 查询点赞关联内容 -> 返回分页
  - 亮点：行为轨迹沉淀；可扩展兴趣画像

- `[GET] /user/content/my/collect`（我的收藏）
  - 流程：接收分页参数 -> 查询收藏内容 -> 返回分页
  - 亮点：与点赞行为分层；支撑长期兴趣资产管理

- `[GET] /user/content/my/browseHistory`（我的浏览记录）
  - 流程：接收分页参数 -> 查询浏览轨迹 -> 返回分页
  - 亮点：行为可观测；可用于召回增强与冷启动优化

- `[DELETE] /user/browse/history/clear`（清空浏览记录）
  - 流程：读取 userId -> 删除历史记录 -> 返回成功
  - 亮点：用户可控隐私清理；写接口幂等友好

- `[GET] /user/{userId}/profile`（公开主页）
  - 流程：接收目标用户 ID -> 查询基础资料+关系状态 -> 返回主页 VO
  - 亮点：聚合展示模型；支持访客态与登录态差异

- `[GET] /user/{userId}/contents`（用户公开内容）
  - 流程：接收目标用户与分页 -> 查询已通过且未删除内容 -> 返回分页
  - 亮点：公开内容口径统一；减少脏数据外泄风险

- `[POST] /user/logout`（退出登录）
  - 流程：读取当前 userId -> 清理会话状态 -> 返回成功
  - 亮点：主动失效机制；提高账号安全闭环

### 模块二：内容发布与互动（19）

## 系统级设计主线（3 条）

- 稳定性主线
  - 核心策略：接口幂等（点赞/关注状态切换）、异常分层（业务异常/系统异常）、可降级（RAG AI 失败不阻塞主流程）、关键状态写入可追踪
  - 建议加强：审核与举报处理链路引入消息重试与死信队列，提升跨存储更新可靠性

- 性能主线
  - 核心策略：分页与滚动分页并用（列表/Feed）、热点计数与会话缓存（Redis）、聚合读模型（profile/trending）
  - 建议加强：搜索与推荐分层缓存、批量接口优先（如 moderation batch）、大字段按需加载

- 安全主线
  - 核心策略：鉴权与角色隔离（用户端/管理端）、内容审核闭环（发布->审核->分发）、举报治理与审计留痕、上传文件三重校验
  - 建议加强：高风险操作审计日志标准化、风控规则版本化、敏感操作双因子校验（管理端可选）

## 术语一致性检查（已统一）
- “帖子/内容”统一口径：业务名可称“帖子”，接口与路径使用 `content`
