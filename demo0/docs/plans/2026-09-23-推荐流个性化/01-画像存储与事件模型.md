## Task 1.2 UserProfileService —— 画像 Hash 读写

**Files:**
- Create: `src/main/java/com/quanta/demo0/service/UserProfileService.java`
- Create: `src/main/java/com/quanta/demo0/service/Impl/UserProfileServiceImpl.java`
- Test: `src/test/java/com/quanta/demo0/service/Impl/UserProfileServiceImplTest.java`

**接口（固定）：**

```java
public interface UserProfileService {

    /**
     * 累加一次行为：查帖子当前标签集合，对每个标签 HINCRBYFLOAT 权重，
     * 并同步累加 __total。帖子已删除/驳回/不存在时跳过（防脏画像）。
     * Redis 异常向上抛（由调用方决定重试语义），不得吞掉伪装成功。
     */
    void applyBehavior(Long userId, Long contentId, double weight);

    /**
     * 读取用户画像（HGETALL）。无画像/用户不存在返回空 Map（不抛异常）。
     * 返回 Map 含 __total（供 α 计算与画像量评估）。
     */
    Map<String, Double> getProfile(Long userId);
}
```

**实现要点：**
- 标签解析：第一版 = `contentMapper.selectById(contentId)` → `auditStatus` 为审核通过且未删除 → `contentType` 映射标签 `life`(1) / `professional`(2)。**标签解析方法独立成私有方法 `resolveContentTags(Content)`**——LLM 标签上线后只改这里（D5 自动生长机制的唯一扩展点）。
- 写入：`stringRedisTemplate.opsForHash().increment(USER_PROFILE_KEY + userId, tag, weight)`，逐标签执行后再 increment `__total`。不设 Hash TTL（D10：不做重建，丢了重新积累）。
- 跳过语义：帖子状态不合法时直接 return（INFO 日志含 contentId），**不累加也不抛异常**（消费侧重试无意义）。
- 依赖注入：`@RequiredArgsConstructor + private final`（照抄同包风格）。

**测试目标（一次写完，先 RED；mock Mapper，真实 Redis 行为由 03 的 Testcontainers 集成覆盖）：**
- 合法帖（type=1 审核通过）：`applyBehavior(uid, cid, 2.0)` → 对 life 与 `__total` 各 increment 2.0。
- 合法帖（type=2）：professional 标签。
- 已删除/驳回/不存在的帖子：零写入、零异常。
- `getProfile`：HashOperations entries 委托、空返回空 Map、null userId 防御。

