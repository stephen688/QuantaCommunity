## Task 2.3 BrowseBehaviorSyncTask —— 浏览对账（扫表转发）

**Files:**
- Create: `src/main/java/com/quanta/demo0/service/Impl/BrowseBehaviorSyncTask.java`
- Modify: `src/main/java/com/quanta/demo0/mapper/BrowseHistoryMapper.java`（+XML，新增增量查询）
- Test: `src/test/java/com/quanta/demo0/service/Impl/BrowseBehaviorSyncTaskTest.java`

**设计（D3：扫表 → 转发事件，削峰 + Inbox 幂等）：**
- `@Scheduled(fixedDelayString = "${quanta.recommend.profile.browse-sync-fixed-delay-ms:600000}")`（10 分钟，可配）。
- watermark：Redis String，key 用常量 `USER_PROFILE_SYNC_WATERMARK_KEY`（`user:profile-sync:watermark`，已处理到的 browse_history.id）。**Task 开始时先核对 `insertOrUpdateBrowseHistory` 的唯一键语义**（(userId, contentId) 还是 (userId, contentId, browseDate)）——首看 SQL 在两种语义下均正确，但测试造数必须与真实唯一键一致。**执行流程**：
  1. 读 watermark（无 → 0）；
  2. `selectIncrementalFirstViews(watermarkId, batchSize)`（新 Mapper 方法），SQL 固定为：
     `WHERE bh.id > #{watermarkId} AND bh.is_deleted = 0 AND NOT EXISTS (SELECT 1 FROM browse_history earlier WHERE earlier.user_id = bh.user_id AND earlier.content_id = bh.content_id AND earlier.id < bh.id) ORDER BY bh.id LIMIT #{batchSize}`——**只取每对 (userId, contentId) 的首看行**（D11：重复浏览同一帖不重复累加，封死"刷详情页刷画像"攻击面）；
  3. 每行发 `createUserBehaviorEvent(userId, contentId, "VIEW")`，eventId = `user.behavior.browse:{browseHistoryId}`（**稳定 ID**：同一行重复转发被 Inbox 幂等挡住）；
  4. 全批发送成功后，原子推进 watermark（SET 为本批最大 id）。**watermark 推进失败/中途异常：不推进**——下轮重扫重叠区间，重复事件被 Inbox 幂等消化，这正是选 MQ 转发而非直接 HINCRBYFLOAT 的原因。
  5. 增量超过 batchSize 时循环直到取空（单轮上限保护，如 20 批，防首跑巨量）。
- 多实例防重：任务级轻量锁（Redis `SET NX EX 600`，key 用常量 `USER_PROFILE_SYNC_LOCK_KEY`；抢不到直接跳过本轮）。锁模式与 2.4 衰减锁统一抽一个小工具或直接两处同写（二选一，实施时看代码量，倾向抽 `RedisTaskLockAdapter` 复用——**仅当两处逻辑一致时才抽**）。**watermark 与两个锁 key 均在 `user:profile-*` 命名空间（D12），严禁写进 `user:profile:` 前缀**——否则衰减任务 SCAN 会把它们当画像 Hash 处理抛 WRONGTYPE。

**测试目标（一次写完，先 RED）：**
- 正常流：watermark 0 → 扫到 3 行 → 3 个 VIEW 事件（eventId 断言稳定格式）→ watermark 推进到最大 id。
- 首看去重（D11）：单测 mock Mapper 按 SQL 语义造数（同对重复行已被过滤）；NOT EXISTS 过滤语义本身由 Mapper 层测试覆盖——同一 (userId, contentId) 只产生一次画像累加。
- 中途发送异常：watermark 不推进；下轮重扫。
- 无增量：零事件、watermark 不动。
- 抢锁失败：直接返回零调用。
- 多批循环：5 行 batchSize=2 → 3 批全处理。

**验证：**

```powershell
mvn -Dtest=BrowseBehaviorSyncTaskTest test
```

- 轻量锁同 2.3（key 用常量 `USER_PROFILE_DECAY_LOCK_KEY` = `user:profile-decay:lock`，TTL 覆盖预计执行时长，如 1800s）。

**测试目标（一次写完，先 RED）：**
