## Task 4.1 API 回归用例改造 + 真实链路验收

**Files:**
- Modify: `docs/api-test/cases/`（P4-01 及所有涉及 `scene=latest/hot` 的 recommend 用例；Task 开始时 grep `scene` 定位全部涉及文件）
- Modify: `docs/api-test/RESULTS.md`

**用例改造要点：**
- `scene=latest` 断言更新：返回画像流/热度兜底语义（登录新用户=热度序；`minScore=null, offset=0`；list 装配完整）。
- 新增 `scene=recommend` 用例：登录用户（有行为画像的用户优先用种子数据）返回画像序；匿名=热度序且与 hot 一致。
- `scene=hot` 断言补强：连续两次拉取不写曝光 set（可通过行为差异验证：第二次结果与第一次可重复，不再因曝光被滤掉/降级重拉）。
- 非法 scene 400 语义不变。

**真实链路验收（本地全栈：MySQL/Redis/demo0 :9191 可用时执行；不可用记 BLOCKED）：**
1. 种子用户对 2 个 life 帖点赞、1 个 professional 帖评论 → 等 MQ 消费 → `HGETALL user:profile:{uid}` 验证 `life=4.0, professional=4.0, __total=8.0`（赞 2×2 + 评 4）。
2. 插入/产生浏览记录 → 触发或等待对账任务 → 画像增加 VIEW 权重；重复触发不重复累加。
3. 该用户拉 `scene=recommend` → life/professional 偏好体现于排序；连续拉取不重复（曝光）；匿名对比热度序一致。
4. 手动触发衰减任务 → 全 field ×0.95。
5. 全部证据（脱敏）记入 RESULTS.md 新小节"推荐流个性化（S-PF）"，状态只用 PASS/FAIL/PARTIAL/BLOCKED。

**验证：**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\docs\api-test\scripts\run-phase.ps1 -Phase 4
```
