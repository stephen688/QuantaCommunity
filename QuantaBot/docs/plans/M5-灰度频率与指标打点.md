# M5-灰度频率与指标打点 实施计划（M5 计划 2/4）

> **For agentic workers:** 本计划按 AGENTS.md §6 工作流执行（步内 TDD 红绿节拍、每任务一提交、完成后独立审查）。git 命令在 `QuantaCommunity` 根仓库执行，路径带 `QuantaBot/` 前缀。
> **前置依赖**：`M5-熔断与成本分档.md` 已合入（本文件复用其 `PipelineDeps` 扩展机制、eval runner 的 `kv_presets`+refresh 预置机制、Decision 枚举追加模式）。

**Goal:** 三个"沉睡"控制面能力接线生效——灰度白名单（放量模式）、persona_version 远程键（回滚演练的开关）、频率约束（同帖/同用户保守值）；补齐指标打点（全程+分段时长、决策日志扩列），让 P95/成功率/成本可从 SQLite 聚合。

**Architecture:** 灰度=放量语义（白名单非空→仅白名单用户放行，空=全量），脏数据沿用上一有效快照（灰度期间键损坏≠全量放开）。persona_version 远程键优先、缺省回落本地 prompts hash——回滚=改键值，旧版本记忆隔离（M3 已实现的 payload 过滤）自动生效。频率计数走 Redis 键 INCR+EXPIRE（滑动窗口），fail-open。时长打点全程+四段（decision/context/generation/write），SQLite decisions 表扩 `duration_ms`/`cost_li` 两列（带迁移）。

**Tech Stack:** 现有依赖，零新包。

**Spec:** `总计划.md` §2 M5 节（M5-灰度与回滚、M5-频率约束两条 checkbox 的代码侧）+ 本文件「需求结论」。grill 共识落地第 6/7/8/18 条（指标观测部分）。

## Global Constraints

- 同计划 1 的 Global Constraints（主模型不动/静默优于乱回/打点纪律/分层/命名/Settings 收口/Conventional Commits）。
- 管线关卡最终顺序（本文件 Task 2 定稿）：⓪kill → ①触发检测 → ②幂等 → **②.5 灰度（新）→ ②.6 频率（新）** → ③审核预检 → ④硬规则低价值 → ④.5 成本读档（计划 1 已插） → ⑤拉取 → ⑥记忆 → ⑦决策 → …。原则：免费的用户级闸（灰度/频率）最早、免费的内容级闸（预检/硬规则）次之、花钱的判断（成本读档之后的一切 LLM 调用）最后；幂等先于一切计数闸（防重复投递重复计数）。
- 不做"按帖灰度"维度（PRD 提及但键设计无落点——共识明确降范围，Phase 2 备选）。

## 需求结论（grill-me 共识摘录）

1. 灰度=放量模式：`quantabot:switch:graylist` 非空 → 只对白名单 userId 回复，其余静默 `skipped_graylist`；空 → 全量放开。
2. graylist 脏数据 → 沿用上一有效快照（不再降级为空——灰度期间键损坏等于事故）。
3. persona_version：远程键有值 → 覆盖本地 hash 作为记忆写入/召回/摘要缓存的版本号；键空 → 本地文件 hash。回滚=改键回旧版本号。
4. 频率保守值：同帖 3 条/48h（滑动窗口，对齐对话链 TTL）、同用户 5 条/24h（滑动窗口，比自然日更保守防跨午夜刷量）；超限静默 `skipped_rate_limit`；被拦的尝试也计数（刷屏者耗尽自己配额）。
5. Redis 故障哲学：频率键读写失败 → fail-open 放行 + WARNING。
6. 时长打点：全程 `duration_ms` + 分段 `stage_ms`（decision/context/generation/write）进 RunTrace（→Langfuse metadata）与 SQLite（decisions 表扩列）。

```python
def parse_snapshot(
    raw: dict[str, str | None], previous: ControlPlaneSnapshot | None = None
) -> ControlPlaneSnapshot:
    """把三键原始值解析为快照（kill/persona 脏值宽容；graylist 脏值沿用旧值——M5 共识）。"""
    kill = (raw.get(SWITCH_KILL_KEY) or "").strip().lower() == "true"
    graylist: tuple[int, ...] = ()
    gray_raw = (raw.get(SWITCH_GRAYLIST_KEY) or "").strip()
    if gray_raw:
        try:
            graylist = tuple(int(x) for x in json.loads(gray_raw))
        except (ValueError, TypeError):
            if previous is not None and previous.graylist:
                # M5：灰度期间键损坏≠全量放开——沿用上一有效快照（放量事故防御）
                graylist = previous.graylist
                logger.warning("灰名单键值损坏，沿用上一有效快照：%r", gray_raw)
            else:
                logger.warning("灰名单键值非 JSON 整数数组，降级为空：%r", gray_raw)
    persona_version = (raw.get(SWITCH_PERSONA_VERSION_KEY) or "").strip()
    return ControlPlaneSnapshot(kill=kill, graylist=graylist, persona_version=persona_version)
```

```python
"""crosscutting/rate_limit —— 频率约束（M5：同帖回复上限 + 同用户日限，保守值）。

职责：两把 Redis 计数闸——quantabot:ratelimit:post:{post_id}（48h 滑动窗）与
      quantabot:ratelimit:user:{user_id}（24h 滑动窗）；INCR 后判，被拦的尝试也计数
      （刷屏者耗尽自己配额——反滥用向设计）。
边界：只做计数与判定，不做拦截动作（管线 ②.6 闸消费本模块返回值落 skipped_rate_limit）；
      滑动窗口=INCR 每次刷新 TTL（比自然日更保守，防跨午夜集中刷量）；Redis 故障由调用方
      fail-open（M5 共识：频率是防滥用不是安全红线，抖动期放行可接受）。
"""

from quanta_bot.crosscutting.ports import KeyValueStore

RATELIMIT_POST_PREFIX = "quantabot:ratelimit:post:"  # 同帖 AI 回复计数（48h 滑动窗，对齐对话链 TTL）
RATELIMIT_USER_PREFIX = "quantabot:ratelimit:user:"  # 同用户触发回复计数（24h 滑动窗）


async def check_and_count(
    kv: KeyValueStore,
    *,
    post_id: int,
    user_id: int,
    post_limit: int,
    post_window_hours: int,
    user_daily_limit: int,
) -> tuple[bool, str]:
    """计数并判定：任一超限返回 (False, 拦截理由)；放行返回 (True, "")。

    语义：先 INCR 后判——第 N+1 次尝试使计数达到 limit+1 即被拦，且计数保留。
    """
    post_key = f"{RATELIMIT_POST_PREFIX}{post_id}"
    user_key = f"{RATELIMIT_USER_PREFIX}{user_id}"
    post_after = await kv.increment(post_key, 1, post_window_hours * 3600)  # 每次刷新 TTL=滑动窗
    user_after = await kv.increment(user_key, 1, 24 * 3600)
    if post_after > post_limit:
        return False, f"同帖回复上限（窗口内第 {post_after} 次尝试 > 上限 {post_limit}）"
    if user_after > user_daily_limit:
        return False, f"同用户频率上限（24h 内第 {user_after} 次尝试 > 上限 {user_daily_limit}）"
    return True, ""
```
