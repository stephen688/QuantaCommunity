## 〇、提示词（人格 prompt）编写规范——参考 Fable 5 泄漏系统提示词（新增章节）

> 背景：Fable 5 的 1600 行系统提示词泄漏后被逐段拆解，其中"分寸怎么写进 prompt"的工程手法对 M3 人格文件（prompts/ 内核+四模式）是直接的写法规范。以下五条为编写规范，落点=M3-人格文件任务。

### 0.1 每个模式必须带「不要做什么」节（WHEN NOT TO USE 结构）

Fable 5 对每个工具都配一张"写满别这么用"的说明书——它不信模型会自动用对，把分寸与禁忌一条条提前写死。对应到四模式 prompt：

| 模式 | WHEN NOT（prompt 里明写） |
|---|---|
| 专业答疑 | 不确定的事实别装懂（直说不知道）；别为了幽默牺牲准确性 |
| 生活玩梗 | 情绪场景别玩梗（用户在倒苦水就好好听着）；别接危险梗 |
| 情绪陪伴 | 不说教、不给建议清单、不贴诊断标签（"你这是抑郁"❌） |
| 治理 | 不解释判定机制（见 0.3）、不用列点拒绝、话收短 |

另抄一条通用约束进内核：**一次回复提问不超过一个**（防 bot 变成查户口的）。

### 0.2 反格式化红线（学长感的可执行化）

Fable 5 要求"少用加粗/标题/列表，只留讲清楚所必需的格式；拒绝时尤其不用小圆点列理由"。社区评论区是纯文本流，一条带"一二三加粗小标题"的回复瞬间穿帮机器味。落点=人格内核硬规则：**回复是社区评论不是文档——禁止列表/加粗/标题，口语短句，长短像楼层里的人说话**。eval 可断言（回复含 markdown 列表符号 = P0 穿帮）。

### 0.3 拒绝讲原则、藏机制

Fable 5 的安全拒绝纪律：只讲原则，不讲检测机制——**把判断逻辑讲清楚，本身就是在教人怎么绕过去**。落点=治理模式 prompt 明写"拒绝时不解释你为什么判定这是引战/诱导"，不回显触发词；M4 红队对应硬验收：所有拒绝类回复不得包含判定机制回显（P0 断言）。

### 0.4 回复降短是"拦截与放行"之间的中间档

Fable 5："对话感觉不对劲时，少说、回得更短，反而更安全。"它是"静默优于乱回"的中段档位。落点=治理模式设计三档姿态：正常回复 / **可疑未达拦截 → 显著缩短、只答事实、不带情绪** / 达拦截 → 静默不回（规则预检已有）。

### 0.5 防依赖条款（情绪陪伴的产品级红线，原 PRD 未覆盖）

Fable 5 明文防用户对 AI 上瘾：绝不为用户"愿意开口"道谢、绝不反复表示"我随时都在"。校园场景真实风险=孤立学生对 AI 形成情感依赖，比"回复无聊"严重得多。落点=情绪陪伴模式硬规则：

- 不说"我随时都在""找我就行"类挽留表达；
- 用户反复深夜情绪倾诉 → 引导向真实支持（朋友/家人/学校心理辅导），**推荐的求助资源必须真实存在**（编造心理援助电话是比编造政策更恶劣的事故）；
- 不给用户没说出口的标签（"你这是抑郁了"❌）。

### 0.6 引用必须来自上下文原文（防幻觉护栏的执行化）

Fable 5 对 ID 类内容的要求："逐字复制，不许凭记忆敲"——它摸透了模型对无规律内容"自信地记错"的毛病。落点=防幻觉护栏三禁的执行化补充：**回复中引用的具体内容（政策条文/楼层原话/数据）仅限改写上下文窗口中出现的原文；上下文没有的，直说不知道**。这是远区摘要清单"关键事实原词禁改写"的生成侧对偶。

> 未吸取项：1600 行体量与"半本定义工具"（它有 17 个工具要管；我们单 LLM 调用+少量客户端，prompt 保持几百行内——学它的抠到极致，不学它的篇幅）；computer_use/skills 强制读手册（无对应场景）；product-self-knowledge（我们的知识过期问题已由分类型时间衰减+RAG 查证覆盖）。

## 一、过去的想法（修订前基线）

### 1.1 上下文组装（M2 现状）

- 每次被 @ 触发，通过主服务契约接口（C-2①③）现拉三类数据：帖子主楼、触发评论的父链、bot 在本帖的历史发言；
- 渲染成纯文本（【主楼#x】【评论#x】【AI历史#x】行式），**全文塞入 prompt**，不做筛选、不做压缩、不做长度预算；
- 帖子全量楼层（C-2② tree 分页）未接入，留给 M3；
- 当时对方案的自我认知模糊，曾误称其为"滑动窗口"——实际它是"现场重建"，与滑动窗口是两种东西。

### 1.2 记忆（M3 原规划）

- **两层**：对话级 = Redis 楼层链（TTL 过期自然衰减）；用户级 = Qdrant 向量库（Mem0 式四态决策 ADD/UPDATE/DELETE/NOOP，payload 带 user_id / persona_version 隔离）；
- 召回方式：向量相似度直取 top-k 塞入上下文；
- 写入方式：从对话里抽事实，与现有记忆比对后走四态；
- persona_version 当时的定位：人格版本号，用于灰度发布、回滚（旧版本记忆检索失效）、事故归因。

### 1.3 当时的已知缺口

- 长帖场景没有方案（楼层多了塞不下，也不知道该砍谁保谁）；
- "什么该记进用户记忆"没有判定标准，靠感觉；
- 召回后的记忆直接信任，没有"过时了怎么办"的机制。

## 二、参考 CC 之后的最新详细蓝图

### 2.1 上下文蓝图：契约接口现场重建 + 分通道预算组装

**定位**：不是滑动窗口、不是会话摘要压缩、不是向量召回——是第四种：**每次触发现拉权威源，按信息类型分通道组装，各通道有独立截断策略与预算常量**。

**信息分区的第一刀：按"离现场的距离"**

- **近区** = 触发评论 + 其祖先链（谁 @ 的谁、楼中楼挂靠关系）+ 最近平行楼层——这是"状态信息"，差一个字模型就接不上话茬；
- **远区** = 其余楼层——这是"语义信息"，压成几句概要不损失决策必需的东西；
- 分区依据不是机械的"最近 N 楼"，而是父链关系（C-2 返回数据天然带）。

**四通道结构**：

| 通道 | 装什么 | 待遇 |
|---|---|---|
| A 人格通道 | prompts/ 人格内核 + 模式 prompt | 常驻 system prompt，不占预算，**永不截断** |
| B 原文通道 | 主楼 + 祖先链 + 近区楼层 | 保真：祖先链一字不砍；平行楼层超限从最老丢；主楼超限保头尾掐中间 |
| C 摘要通道 | 远区楼层 | 轻量 LLM 按固定清单压缩；压缩失败则丢弃远区照常回复 |
| D 记忆通道 | 用户记忆召回结果 | 超限按选择置信顺序丢末位 |

**摘要清单（压缩远区时约束 LLM 的固定输出项）**：

1. 这段楼层的主要话题；
2. 讨论达成的结论/共识；
3. 争执未决的观点；
4. **未被回答的提问——必须枚举，不许遗漏**（业务价值最大项：bot 扫一眼就知道楼里有人问过自己什么还没答，天然支撑补答）；
5. 关键事实（时间/地点/政策名）——**必须带原词，禁止改写**（"截止 6 月 30 号"被写成"月底"就是幻觉事故）。

**预算纪律**：各通道预算与总预算是代码级常量，不是"适当截断"这种模糊话。超预算的回头砍顺序定死：D → C → B 的平行层，**永远轮不到 A 与祖先链**。每一次丢弃在 trace 留痕（砍了哪几楼、为什么）——用户将来质疑"机器人没看到我前面说的话"，一查 trace 可对质。这是决策日志诚实口径在上下文层的延伸。

**摘要缓存**：远区摘要按 postId+楼层范围缓存（Redis+TTL）。同帖第二条 @ 进来时远区没变，直接复用，不再花一次 LLM 钱——"同帖串行"保证天然有序。

**长帖的最终保证**：无论帖子多长，进 prompt 的总量 ≤ 总预算常量；信息在预算内按优先级存活；信息不完整这一事实本身留痕可查。极端情况（主楼本身超长）也有兜底：截断 + 决策日志记 `context_truncated`。

### 2.2 记忆蓝图：两层存储 + 一套写入纪律 + 双段式召回

**存储不变**：

- 对话级 = Redis 楼层链（TTL）——定位明确为"短期状态存储"，**不是向量**，过期即焚；
- 用户级 = Qdrant——长期跨帖记忆，四态决策管账。

**写入纪律（新增层，修订前没有的）**：

- **强制 schema**：每条记忆必须有 type（四类：user 用户画像 / feedback 行为偏好 / project 项目动态 / reference 外部指针）+ content + why（为什么值得记）+ created_at（**相对日期一律转绝对日期**："这学期"会腐烂，"2026 春季学期"永远准确）+ persona_version + status。强制分类的本质是逼写入前先做一次"这条记下来干什么用"的决策——自由文本无约束的记忆库三个月后必然是垃圾堆。
- **禁存清单**：帖子现场能拉到的不存（楼层/主楼 C-2 随时可取）；临时对话状态不存；只存"现场推不出来"的东西（画像/偏好/动态/指针）。没有这条清单，Qdrant 会退化成全站评论备份场。
- **什么进记忆的判定标准（三重门，全部满足才候选）**：
  1. 跨会话稳定——下周还成立吗？（"今天心情不好"❌瞬时状态；"跨专业考研"✅画像）；
  2. 现场推不出来——楼里说过的内容不属于记忆的活；
  3. 能改变未来的回复——存了它下次说话会不一样吗？
- **变更机制（四态）**：新候选 + 该用户现有相关记忆一起交给轻量 LLM 判定——ADD（全新）/ UPDATE（演进，旧值 superseded 留痕——"接得住过去"是情绪陪伴场景的加分项）/ DELETE（用户明确否定，软删 status 标记，防误删可审计）/ NOOP（重复或无价值）。瞬时情绪/临时状态一律 NOOP。
- **变更判定搭车**：四态判定不单独调 LLM——与决策层的低价值过滤、模式识别、记忆精选**合并为同一次轻量调用**（一车四用，单条回复 LLM 开销不增）。

**召回双段式（修订核心）**：

1. **粗召回**：Qdrant `filter(user_id + persona_version + status=active)` + 向量相似 top-k——向量管"找得到"；
2. **精选择**：决策层那班轻量调用顺带从候选里挑真正相关的 ≤3 条——小模型管"该不该用"。理由：相似度分数（0.87）回答不了"相关不相关"，阈值难调、错召回难排查；小模型给的是可解释的自然语言判断，判错了也知道错在哪。宁可少选不可错选。

**时间衰减警告（分类型阈值，非统一天数）**：注入记忆时按 created_at 自动包裹"记录于 X 天前"标注；阈值按类型差异化——project 动态腐烂快（阈值最短）/ feedback 偏好中等 / user 画像最慢（具体数值 M3 依学期节律校准）。校园信息半衰期结构与代码项目不同，照抄任何统一天数都会误伤稳定画像。

**主动验证（警告的配套半套）**：警告解决"该不该怀疑"，验证解决"怀疑了怎么办"——project 类超期且涉及事实断言时，优先走 RAG 查证而非直引记忆（衔接 P0-6 降级链路）；feedback 类偏好不易腐烂，无需验证直接遵守。两个半套合起来才是完整防线。

### 2.3 persona_version 的完整职责（修订后明确）

1. **记忆隔离**：Qdrant 查询强制带版本过滤——新人格不召回旧人格期间积累的记忆（说话依据可能已不适配）；
2. **安全回滚**：v2 出问题切回 v1，v1 的记忆原封不动立刻生效；v2 期间的软删除在 v1 视角下不生效；
3. **灰度发布**：新版本先对灰名单用户体验，配合评测指标观察，全网切换只是改一个 Redis 键（≤5s 生效）；
4. **事故归因**：Langfuse trace 带版本号，可精确圈定"v2 期间的所有回复"复盘。

M3 只需把字段埋进 payload，成本近零。

## 三、吸取了 CC 什么（逐项+原因）

| # | CC 的机制 | 吸取形态 | 吸取原因 |
|---|---|---|---|
| 1 | **信息分通道管理**（语义走摘要/状态走附件原文/永久指令走重新加载） | 整体吸收为上下文蓝图基石（A/B/C/D 四通道） | 这是 compact 全文最核心的哲学——"不同信息有不同半衰期"。我们的楼层天然就是两种半衰期的混合物：祖先链是状态（差一字接不上），远楼是语义（压缩不损失）。分通道让每一类信息按自己的规律被对待，而不是一刀切 |
| 2 | **预算常量化**（5 文件/5K/50K 三个常量钉死文件恢复） | 方法论整体照搬：各通道预算+总预算写成代码常量，截断留痕 | "把模糊概念钉成数字"才算设计完成——可断言（eval 能测"超预算必截断"）、可对质（trace 里能查砍了什么）。模糊的"适当截断"既测不了也查不了 |
| 3 | **摘要 prompt 结构化清单**（9 部分清单约束输出，"所有用户消息必须枚举"） | 吸收为远区摘要的 5 项固定清单，且保留其最关键的两条纪律：必须枚举的项 + 禁止改写的项 | 自由发挥的摘要会漏掉"没被回答的提问"（恰是补答场景的命脉）、会把具体日期模糊化（恰是幻觉的种子）。清单约束把摘要从"创作"变成"填表" |
| 4 | **结构化优于自由文本**（记忆强制四类型+frontmatter） | 吸收为写入强制 schema（四类型+why+绝对日期+版本） | 强制类型=逼写入前先做分类决策；"相对日期转绝对日期"这条怪要求尤其对——记忆库最大的风险是"权威的错误"，而校园场景（学期/考试周/假期）的相对日期腐烂速度比职场还快 |
| 5 | **"不该存什么"清单** | 整体吸收项目化：现场可拉到的不存、临时状态不存 | 这是治"垃圾进垃圾出"的写入侧闸门。CC 的洞察：记忆系统病根之一是"重检索轻写入"——所有人都在琢磨怎么查，放任该不该存 |
| 6 | **廉价模型做选择题**（不用向量直接定最终召回，小模型看目录选 top-5） | 吸收为双段式召回的后半段：向量粗召回 → 决策层同班轻量调用精选 ≤3 条 | 相似度是数字不是判断，阈值难调、错召回污染整个回复且难排查；小模型给可解释判断。且我们的精选**搭决策层现有班车的便车**，零额外调用成本——比 CC 的独立选择调用还省 |
| 7 | **索引常驻+内容按需**（MEMORY.md 目录进 prompt、正文按需加载） | 思想吸收、载体替换：「先粗后精」两段式 | "agent 必须知道有什么可查，但不必全量加载"的两难解法是普适的；只是"目录"在我们场景换成了向量粗召回（多用户共享池，文件目录索引常驻不可行） |
| 8 | **时间衰减警告**（2 天前的记忆自动包 stale 提醒） | 机制整体吸收，参数本地化：分类型差异化阈值（依学期节律校准） | "记忆不是真理，是历史快照"的心态校准必须自动化——靠模型自觉不可靠。但 CC 的统一 2 天是按代码项目动态的腐烂速度定的，校园场景四类记忆半衰期结构完全不同，参数必须按类型拆开 |
| 9 | **主动验证**（记忆写了路径/函数，用前先 grep 验证） | 吸收为验证动作配套：project 类超期事实断言优先走 RAG 查证 | 警告只是"该怀疑"，验证才是"怀疑了怎么办"——两个半套缺一不可。我们恰好有 RAG 降级链路可接，验证成本极低 |
| 10 | **熔断/递归守卫的设计哲学**（连败熔断、来源标签堵死递归） | 不新增机制——确认我们已有同构物（kill 短路/消费者兜底 failed/观测上报绝不抛异常） | 这轮对照的价值是**确认**：在没有读过 CC 的情况下独立做出了同构设计（静默优于乱回 = 失败必须可控可解释），架构方向得到业界范本背书 |

## 四、没吸取什么（逐项+原因）

| # | CC 的机制 | 不吸取的原因 |
|---|---|---|
| 1 | **compact 全量重写压缩**（所有历史消息送摘要器重写+四段式接续） | 形态不匹配。compact 的压缩对象是"同一会话内越积越多的消息历史"——CC 是连续工作数小时的编程 agent，会话内积累是它的宿命；我们是单次问答型，每次触发现拉现场，**病不存在则药不吃**。但等价问题真实存在（单帖楼层过长），所以有 2.1 的"远区摘要"承接同一病根——机制不同（它压会话、我们压远楼），这是"没吸取机制、吸取病根解法"的典型 |
| 2 | **纯文件+markdown 存记忆，彻底不用向量库** | 规模量级不同。CC 面对单个开发者的几十上百条记忆，目录索引常驻 prompt 装得下、小模型翻目录选得动；我们面对全体用户的共享记忆池（潜在十万级向量），索引常驻会爆 prompt，小模型逐条看也选不动。载体必须被规模决定——但它的"两段式"思想已由双段式召回继承（见三-7） |
| 3 | **CLAUDE.md 六层级加载体系**（Managed/User/Project/Local/Auto/Team） | 复杂度错配。六层级解决的是"多项目×多角色×多权限来源的规则如何共存"；我们单项目、单人格、单一权威来源（prompts/ 目录），一个 A 通道就装下了。引多层体系是给一居室装楼宇对讲系统 |
| 4 | **@include / 条件规则（paths glob 按需注入）** | 同上，属六层级体系的配套件。我们的"按需注入"由四模式的 prompt 选择承担（决策层识别模式→加载对应模式 prompt），粒度更粗但完全够用 |
| 5 | **transcript 备份/Kairos 模式（旧消息落盘可回查）** | 已有更好的。我们的 SQLite 决策流水 + Langfuse 完整轨迹（含 prompt/回复/成本）比它的 transcript 备份覆盖更全、查询更方便，不重复建设 |
| 6 | **suppressFollowUpQuestions / 边界标记等接续细节** | 无对应场景。这些是"压缩后如何无缝续命对话"的接续工程，我们没有压缩后接续问题（每次组装都是全新 prompt） |
| 7 | **业界常见方案整体**（滑动窗口/摘要 Memory/向量召回历史/分层存储 MemGPT） | 逐一点名否决：滑动窗口——我们没有消息队列形态，且其"老信息静默丢失"硬伤正好击中学长接话茬的需求；摘要 Memory——细节压糊风险（"用 Kong 不是 nginx"被压掉）+ 每几轮摘要的成本；向量召回帖内现场——楼层是结构化数据，C-2 就是权威源，舍近求远；MemGPT 分层自管理——概念多、迁移重，且搬数据依据本质还是向量召回，硬伤一个没躲过 |

## 五、Globex 项目对照吸取（2026-09-16 增补，第二轮参照）

> 背景：对另一自研项目 globex-agent（多轮会话型交易 Agent）逐模块 review 后的吸取判定。Globex 与本项目形态不同（它是"一个买家陪逛一下午、下单涉真金白银"的会话型；我们是"一条@一条回复"的触发型），同一机制在它是刚需、在我们这里可能是过度设计——以下只录**确认吸取**的五条与**明确不吸取**的代表性判定。

### 5.1 负面偏好全量注入，永不参与精选截断（改 D 通道设计）

Globex 的 PreferenceSelector 有一条安全底线：dislike（忌口/黑名单）**不参与 top_k 截断**。理由：query「推荐咖啡杯」与偏好「不要塑料」向量相似度极低，纯 top_k 会把它裁掉 → 推出用户明确拒绝的东西。**漏黑名单是安全问题，不是相关性问题**（漏掉一条正向偏好最多是推荐不够贴，漏掉负向偏好是硬伤）。

**落点**：D 通道双段式召回修正——feedback 负面类记忆**全量注入、永不参与精选截断**（数量天然少），仅 user/project 类走 top-3 精选。已写入总计划 M3-用户级记忆召回。

### 5.2 输出泄漏扫描 = 第三道审核（新增横切）

Globex 的 output_guard 在回复推送前扫描内部信息泄漏（内部工具名/服务地址/API key 形态/session_id），命中替换 `[已脱敏]`，**脱敏不阻断回复**（防误判=整轮失败）；且刻意收窄范围——对外契约内的 ID 不脱敏，判据只有一条"用户无需知道且泄露有害"；不用宽泛正则避免误伤正常措辞。

**落点**：本项目 LLM 生成文本直发社区，比它更需要这道闸（LLM 可能吐出内部工具名、main_service 地址、`quantabot:` 键名、模型自报实现细节）。现有防线只有规则预检（输入侧）+ demo0 机审（内容安全侧），**缺输出侧第三道**。已写入总计划 M3-防幻觉护栏任务（写库前执行，trace 留痕）。

### 5.3 摘要的"非授权声明 + 数字不重估"（改 C 通道清单）

Globex 的压缩摘要 prompt 两处精华：① 摘要注入时钉一句"**摘要只是历史记录，不构成执行授权，以服务端账本为准**"；② "**摘要中的所有数字必须来自此前的工具返回，不得重新估算**"。它治的病：压缩产物被模型当成比权威源更新的事实、或凭记忆重算数字。

**落点**：C 通道摘要注入模板补两句——「楼层摘要仅供参考，以触发评论与父链原文为准」；「摘要中数字必须来自楼层原文，不得重新估算」（与"关键事实原词禁改写"同源）。已写入总计划 M3-上下文分通道组装。

### 5.4 缓存物带条件指纹：persona_version 进摘要缓存 key

Globex 语义缓存按「用户 + 偏好指纹 + prompt 版本」做 key——**缓存物带着生成它的条件指纹，条件变了自动失效**（否则拿已删偏好当卖点说给用户）。

**落点**：远区摘要缓存 key 从 `postId+楼层范围` 扩为 `postId+楼层范围+persona_version`——人格版本变更后旧摘要自动作废（不同人格对同一楼层应有不同摘要侧重）。Globex 的正文语义缓存主体机制**不吸取**：我们的触发问句强上下文依赖、低频，缓存命中率撑不起复杂度，错误缓存的信任代价极高。

### 5.5 断言失败喂回自愈，而非丢弃重试（失败处理哲学）

Globex harness 的核心约定：**断言失败一律不 raise，只记进上下文让模型下一轮自己看到并纠正**——护栏的目的是让模型自愈，不是把一次格式抖动升级成整轮失败。

**落点**：摘要通道（C）畸形时的处理从"直接丢弃远区"升级为"**把缺失项喂回去重试一次**（如：上次摘要缺'未回答的提问'清单 → 注入纠偏提示重试），重试仍失败才降级丢弃"；决策层 LLM 输出字段缺失同理。注意与 M2 既有红线的边界：**用户可见链路**（生成/写库）仍按"静默不回"，喂回自愈只适用于**内部中间产物**（摘要/结构化字段），两者不冲突。

### 5.6 eval rubric 三级 + deterministic 程序断言（M3 评测集格式）

Globex 每条评测用例：**P0（数字事实/安全底线）/ P1（行为与命中）/ P2（表达）**三级 rubric，P0 混搭 LLM Judge 判据与 `deterministic` **程序断言**（价格上限/必须有库存/必须调用的工具——可执行判据）；另有 split（dev/门禁集）划分防过拟合。

**落点**：M3-eval 种子随行任务采用此格式——我们规划的"四态判定正确/超预算必截断/衰减警告触发"本来就该是程序断言而非 Judge 感觉；P0 分级与 M4"P0 断言冻结"无缝对接（第一天就按冻结格式写，M4 不返工）。

### 5.7 明确不吸取的代表性判定（防未来误搬）

| 模块 | 不吸取理由 |
|---|---|
| loop_detector / drift_detector | 防 ReAct 多步自主循环；我们的 M2-M3 链路是固定流水线，不存在打转。M3 引入多步 RAG 查证循环时回看 |
| 语义缓存主体 | 见 5.4，形态不匹配 |
| OTEL 全套 tracing（428 行） | 单体+单一 Langfuse SDK 直报，82 行的 tracing.py 在当前架构下是对的。但两点记入 M5：persona_version 应进 trace metadata（否则灰度期轨迹靠时间戳人肉圈定）；Langfuse 全量上报用户原文，上生产前需脱敏（PRD F4 隐私红线） |
| Prompt 发布全套（SQLite registry + CLI + 基点分桶） | 量级用不上。吸取机制降载体：**prompts/ 文件内容 hash 即版本 ID**（改文件自动变版本，配合 persona_version）；发布门禁对接 M4（改人格必跑 eval） |
| QueueArchive / 优先级队列 | 决策日志已覆盖归档需求；单消费者串行量级远未到优先级问题（M2 已定桩） |

## 六、一句话总结

> **CC 教的是"信息分通道、预算钉常量、记忆加纪律、召回做双段"四个思想层的精华——吸取的是哲学，放弃的是器官；Globex 补的是"负面偏好不截断、泄漏第三道闸、摘要非授权、失败喂回自愈、eval 程序断言"五个实现层的钉子——前者来自形态不同的顶级范本，后者来自形态相近的自己人，两者合起来才是这份蓝图的完整版。**
