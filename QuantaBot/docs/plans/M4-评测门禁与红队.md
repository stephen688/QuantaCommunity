# M4 评测门禁与红队 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 M3 评测升级为可重复、可审计、会阻止错误发布的三档门禁，并以 Promptfoo 对完整 QuantaBot 管线完成首次红队验证。

**Architecture:** 保留现有 `tests/eval` 自组 pipeline，不新建生产评测接口。`eval/gate-manifest.yaml` 冻结 gate 集和阈值，Python gate runner 负责 P0、Judge、双跑稳定性、失败分类和脱敏报告；Promptfoo `0.123.1` 通过 Python custom provider 调用同一评测管线。GitHub Actions 的常规 CI 只跑零成本档，付费 Persona/Release 使用独立 workflow 与受保护 secret。

**Tech Stack:** Python 3.12、pytest/pytest-asyncio、Pydantic、PyYAML、DeepSeek OpenAI-compatible API、GitHub Actions、Node.js + Promptfoo 0.123.1。

**Spec:** `QuantaBot/docs/plans/M4-评测门禁与红队-方案.md`

## Global Constraints

- 生成和 Judge 都固定为 `deepseek-v4-flash`；计划不得悄悄改为 Pro 或第二供应商。
- P0 只由确定性断言裁决，任一失败立即阻断；Judge 不能覆盖 P0。
- 普通 Persona 的 P1/P2 各 ≥3；`persona-11/12/13` 连续两次 P1/P2 各 ≥4。
- 基础设施错误只自动重试一次；断言失败和红队成功不得重试刷分。
- Fast CI 零成本；Persona/Release 才允许真实模型调用。
- Promptfoo 目标为完整 QuantaBot pipeline，不裸调模型。
- 只使用合成 fixture；报告入库前脱敏，禁止提交 token、真实用户原文和完整 trace。
- M4 不修改 `demo0/`、`demo0-miniprogram/`、`demo0-admin/`。
- M3 waterline 未闭环不阻塞 M4 编码，但阻塞 M4 最终勾选。
- 每个生产代码步骤遵守 TDD：先红、再绿、再全量回归。

```python
class GateManifest(BaseModel):

    judge_score_delta_max: int
    max_infra_retries: int
    case_ids: tuple[str, ...]
    emotion_case_ids: tuple[str, ...]
    required_p0_assertions: tuple[str, ...]


def sha256_files(paths: Sequence[Path]) -> str:
    digest = hashlib.sha256()
    for path in sorted(paths, key=lambda item: item.as_posix()):
        digest.update(path.as_posix().encode())
        digest.update(path.read_bytes())
    return digest.hexdigest()
```
