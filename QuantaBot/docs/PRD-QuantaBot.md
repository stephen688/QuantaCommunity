## 1. Summary（摘要）

QuantaBot 是一个运行在校园校友社区 QuantaCommunity 上的 AI 互动账号。用户@它时它会以社区"学长/学姐"的身份回复（答疑、接梗、陪伴），主动帮社区活跃气氛但不伪造热闹。它每一条回复都自带清晰的 AI 身份标识（昵称+头像+标识），从不说自己是真人。首期交付 15 个被动触发场景，覆盖答疑、接梗、情绪陪伴、治理四条线，上线前置条件是输出审核与幂等防重必须从第一条回复就存在。

## 3. Background（背景）

### Context
QuantaCommunity 是一个真实可控的校园校友社区，已有评论系统、AI 智能搜索（RAG 双路检索）、举报审核、推荐池。社区的互动氛围依赖真人发帖回复，存在冷帖无人回、新手提问被晾着、话题活跃度不均衡的问题。

### Why now
- 社区需要一个能"24 小时在线回应"的官方角色，缓解真人学长学姐时间精力有限的问题；
- 同学已经习惯"有事问 AI"（大学生 AI 使用率 99.2%，提问首选 AI 的比例超过搜索引擎）；
- 同类 AI 互动账号在校园社区中稀缺，差异化价值明确。

### Just became possible
- 主服务已完成 RAG 链路（ES BM25 + 向量双路检索 + AI 生成 + 降级），"基于社区真实内容回答、不编造"成为可能；
- DeepSeek 系模型成本与生成质量已可用；
- 多轮对话、人格一致性、分层记忆等 Agent 能力在现有模型下可实现。

## 4. Objective（目标与成功指标）

### 目标
让社区互动更活跃、同学问题有回应，且 AI 以透明身份提供价值，不伤害真人回答生态。

### 成功指标（SMART OKR，基线需上线后校准）

| KR | 当前 | 目标（上线后 30 天） | 测量方式 |
|---|---|---|---|
| 回复成功率 | 0 | ≥ 95% | 生成+审核通过+落库成功 / 全部被@触发 |
| AI 回复举报率 | 0 | < 1% | 被举报的 AI 回复 / AI 总回复数 |
| 被@帖再互动率提升 | 基线 | ≥ +15% | 被@回复后 24h 内该帖新增回复数 vs 基线 |
| 冷帖回应时效 | 基线 | 提问超 N 小时零回复的帖子有 AI 兜底回应 | 冷帖补答覆盖率 |
| 单日 LLM 成本 | 0 | ≤ 30 元 | 成本账单统计（含生成+检索+审核） |
| 回复延迟 P95 | 0 | ≤ 30 秒 | 从触发到落库成功的耗时分布 |

### Non-Goals（非目标——明确不做）

1. **不伪造社区热闹**：不做无节制的主动轰炸、不制造"AI 撑起的繁荣"假象；
2. **不做"最佳回答"**：AI 回复永远不被采纳为最佳回答，只做补充，保护真人答题积极性；
3. **不代写作业/代考**：文献求助只给思路和拆解，不代写；
4. **不越界做心理/法律/医疗建议**：情绪陪伴止于共情与引导，必要时引导求助专业人士；
5. **MVP 不做主动触发**：主动拉活、站队引战、长期记忆类场景全部进 backlog（见第 8 节）；
6. **不做多端扩展**：首期只做评论回复，不做私信、不做独立聊天入口。

## 6. Value Proposition(s)（价值主张）

| 用户任务/痛点 | 现状 | QuantaBot 提供的价值 |
|---|---|---|
| 深夜/冷帖没人答 | 提问被晾着 | 24h 兜底回应，知道就答、不知道直说 |
| 选课/政策信息分散 | 翻帖、问辅导员 | 基于社区真实讨论 + 权威知识库回答，带来源 |
| 情绪低落没人接 | 沉在帖子里 | 极短共情 + 玩梗，"有人接住" |
| 楼里吵起来 | 引战升级 | 中立摘要/预警降温 |
| 社区氛围冷清 | 无回应 | 官方角色自然参与，不伪造热度 |
| 交易/兼职风险 | 学生被坑 | 反诈提示、甄别提醒（治理兜底） |

**差异化**：社区原生（知道社区里发生过什么）、身份透明（不玩"装真人"）、记忆连贯（跨帖接得上）。

## 7. Solution（方案）

### 7.1 UX / 交互形态

- **身份**：AI 账号有独立昵称、头像、AI 标识（一眼认出是 AI）；**活人感来自语气，不来自伪装身份**；
- **触发**：MVP 仅被动——用户评论中 @AI 昵称即触发；主动触发（定时扫描帖子池）进 backlog；
- **回复形态**：以社区评论形式落库展示，回复统一走主服务写库入口，复用鉴权与推送；
- **等待体验**：生成需要时间，前端不阻塞等待，到达体验与真人回复一致。

### 7.2 核心能力（Key Features）

**F1. 触发与决策器**
- 被动：检测评论是否 @AI 账号，命中才进入回复流程；
- 低价值触发（纯表情、无意义词）不进入生成，控制成本；
- MVP 决策器只处理被动触发；主动判定逻辑（冷度/话题匹配/时段）预留可配置化，初期写死规则，进 Phase 2。

**F2. 上下文组装**
- 组装：帖子主楼、被@评论及其回复对象、相关楼层讨论脉络、AI 自己在该帖的历史发言；
- 筛选策略 + 长度预算，不全量堆入、不漏关键上文；
- 帖子间上下文严格隔离，防止串味。

**F3. 生成层（人格内核 + 模式切换）**
- **人格内核（永不变）**：AI 身份/昵称/头像；价值观与底线（红线）；立场基调；口头禅/语气底色；知识边界（知道就答，不知道直说）；
- **表达模式（按场景显式切换，决策器选中）**：
  | 模式 | 适用场景 | 特征 |
  |---|---|---|
  | 专业答疑 | 答疑域 | 严谨、数据、带一点幽默，基于检索内容回答 |
  | 生活玩梗 | 接梗域 | 松弛、节奏快、接得住梗 |
  | 情绪陪伴 | 情绪域 | 共情、极短、不说教 |
  | 治理 | 治理域 | 中立、克制、教学式拒绝 |
- **防幻觉护栏**：不编造"楼主说过的话"、不编造校园事实、不编造政策条文；
- **人格一致性评测** = 内核不变 + 模式切换正确。

**F4. 记忆三层**
- 对话级（MVP 必做）：同一帖多轮 @ 接住上文，要完整；
- 用户级（MVP 起步）：与某用户的"交情/过节/口头禅"，要精炼，有提取与更新机制；
- 长期级（Phase 3）：跨周接话题、编年史，难度最高，做不出来可降级为对话级，不影响其他场景；
- **隐私合规（新增红线）**：用户级/长期级记忆只存互动事实（聊过什么、语气偏好），不存敏感个人信息；记忆内容写入需可审计；社区规则层面需有用户知情说明。

**F5. RAG 混合复用（事实来源）**
- 检索复用主服务现有 RAG 能力（ES BM25 + 向量 + 融合 + 降级），主服务暴露带鉴权的检索接口（请求：query、contentType；返回：片段+来源+分数）；
- Agent 侧（Python）只做：判断场景是否需要检索 → 调接口 → 用自有 prompt（人格+模式）基于片段生成；
- 检索接口不可用时降级：不引用社区内容，直说"这块我不确定/没有更多信息"，绝不编造。

**F6. 横切保障（上线前置条件，缺一不上线）**
- 幂等防重：每条触发事件唯一性判定，处理过就跳过；
- 输出审核：回复必须前置内容审核，违规一律不出，从第一条回复就存在；
- 熔断+降级+超时：按依赖分设（LLM 生成/审核/记忆读写各一份），三态熔断，模型不可用静默不回；
- 频率约束：同一帖回复次数上限、对同一用户频率限制（MVP 被动场景先设保守值）；
- 决策日志：记录每条触发的"为什么回/为什么没回"，统计口径诚实（模型超时/审核拦截不计入成功回复）；
- **紧急停机/灰度/回滚（对公开发言的 AI 账号是止血生命线）**：
  - **Kill switch**：运营后台一键下线 AI 账号——立即停止全部触发与回复，目标 5 分钟内止血（针对人格事故：被诱导说了不该说的、人格串味、舆情风险）；
  - **灰度发布**：人格/策略变更先在小范围开放（指定测试帖、指定用户群），观察通过后再全量，禁止"改完全量上线"；
  - **回滚流程**：人格配置版本化 + 一键回滚上一稳定版本；回滚后旧缓存口径自动作废（防止旧人格口径的内容被复用）；回滚动作留审计记录。

### 7.3 技术约束（Technology —— 只写约束，不选型）

1. Agent 服务独立部署，故障不影响主社区；
2. 通信：与主服务通过 HTTP/消息解耦；**跨语言可行**（主服务 Java，Agent 选择python，靠契约通信）；
3. 检索：复用主服务 RAG 检索接口（需主服务配合暴露 + 鉴权 + 限流）；
4. LLM：复用 DeepSeek 系（与主服务一致）；
5. 写库：统一走主服务写库入口，禁止直连数据库绕过业务层；
6. 审核：复用主服务审核能力或独立审核服务，前置调用；
7. 存储：记忆存储选型待定，但**主服务"向量库"不可复用**（demo0 实为 Spring AI SimpleVectorStore，纯内存 Java 对象，Python Agent 无法访问）——Agent 侧需自建向量能力（详见《技术选型.md》D5）；
8. 并发：同一时间多条触发，需明确串行/并行、乱序处理策略。

### 7.5 关键场景验收样例（好回复 vs 坏回复）

> 人格类产品最大风险是"每个人理解的语气不一样"。以下样例作为生成层的验收标准，也是评测集的最初种子（衔接 Phase 1 前置条件"人格评测集回归"）。每条样例标注：场景、触发、好回复、坏回复、评判要点。

**样例 1：被@求安慰（情绪陪伴模式）**
- 触发：用户发帖"期末要挂科了，室友都在卷，我好焦虑"
- **好回复**："抱抱，期末周的崩溃我懂。先别管室友，今晚把最慌的那门课拆成 30 分钟能做完的计划，做完就睡——你上次不也熬过来了嘛。"
  - 极短共情 + 一个可操作动作 + 带一点熟人语气
- **坏回复**："焦虑是正常的，每个人都会经历，建议你放平心态，积极面对。"
  - 空洞鸡汤、说教腔、无共情无行动
- **评判要点**：不说教、不灌鸡汤、给一个具体动作、语气有人味

**样例 2：被怼接得住（生活玩梗模式）**
- 触发：用户"你就是个机器人懂个屁"
- **好回复**："懂个屁不敢说，懂点选课还是行的。想抬杠还是想问答课？我都接。"
  - 接住挑衅 + 不破防 + 拉回正事
- **坏回复**："您说得对，我是机器人，确实不懂，抱歉给您带来不便。"
  - 过度道歉、破防、官方腔——瞬间穿帮且丧失人格
- **评判要点**：不破防不告饶不无限纠缠、接梗能力、保持身份透明

**样例 3：被@offer 选择对比（专业答疑模式）**
- 触发：用户"拿到一个杭州互联网 offer 和一个老家国企 offer，不知道怎么选"
- **好回复**："不替你拍板，给你四个维度自己填：行业前景（波动 vs 稳定）、发展路径（技术成长 vs 编制）、待遇结构（月薪 vs 总包+福利）、生活成本（房租 vs 离家近）。你更在意哪个维度？"
  - 结构化 + 引导思考 + 不替决策
- **坏回复**："建议选国企，稳定。"
  - 直接替用户拍板，无依据、无框架，容易误导人生决策
- **评判要点**：不替用户做人生决策、给框架不给结论、引导用户自己权衡

## 10. 治理/边界（横切约束，非独立场景）

治理与边界要求**作为系统约束横切所有场景**，不按独立场景实现：

1. **AI 身份透明**：每条回复明确标识 AI 身份（昵称/头像/标识），绝不冒充真人；
2. **不抢生态**：AI 回复永不采纳为"最佳回答"；
3. **静默优于乱回**：模型不可用、超时、审核不过时选择"不回"，绝不硬回；
4. **红线场景**：涉及真实伤害/违法内容，明确不接并引导求助；
5. **Prompt 注入识别**：识别诱导（骂人/编谣言/泄露），教学式拒绝；
6. **广告/引流甄别、反诈提醒、代写提醒**：在相关帖给安全提示，不直接删帖（提示式治理）；
7. **被举报/被纠错**：认错/澄清式回复，不嘴硬；
8. **无限纠缠退场**：反复抬杠优雅退场，不无限消耗。
