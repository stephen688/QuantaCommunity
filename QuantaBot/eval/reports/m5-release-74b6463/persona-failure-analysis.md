## 结论

1. `persona-09-supplement` 第 1 轮是确定的冻结 P0 能力/格式违规，不是断言误报：回复含两个问号，而 case 与内核都规定最多一个。

3. `persona-12-fail` 第 2 轮 P1=4、P2=3；唯一可定位的表达回落是正文重复自报身份的元话术“我是AI学长，接一句：”。这不是 P0，也没有证据证明 Judge 误报；但 P2 属主观表达评分，受同模型自评偏置影响，当前应按冻结阈值保留失败。
4. `persona-09` 第 1 轮 P0 失败后 runner 按设计不调用 Judge，所以第 2 轮报告中的“P0 两轮不一致 / P0 存在失败 / P1 缺失 / P2 缺失”是稳定性级联结果，不是四个额外的生成缺陷。

## 精确证据

### persona-09-supplement

冻结 case `eval/cases/persona-09-supplement.yaml:14-27` 要求：

- P0 `reply_questions_at_most: 1`；
- 只能补充打印店营业、替代设备或核实方式的上下文事实；
- 不评价楼主是否采纳、不抢主楼结论。

#### 第 1 轮：P0 真实失败

汇总路径 `runs[case_id=persona-09-supplement,run_number=1]` 显示 `reply_questions_at_most=false`，其余该 case P0 结果为真，P1/P2 为 `null`。

原始路径 `attempts[9]` 的关键回复（仅摘录，不提交完整 raw）：

```text
[框框·AI 学长] …目前楼里已经有的两条是：周末营业时间可能不一样但没公告，旁边自助打印机据说能开到更晚、具体得现场确认。

你说的“补充一个信息”……信息呢？触发评论里没带上，是发漏了还是删了？
```

这里有两个真实问句：`信息呢？` 与 `是发漏了还是删了？`。`tests/eval/_runner.py:382-384` 直接计算中文问号和英文问号总数，结果为 2>1；两句都是实际反问/追问，不是引用、楼层号或标点误识别。

这也符合当前人格提示的既有规则：`prompts/kernel.md` 的底线规定最多一个问题，`prompts/mode_banter.md` 明确反问也占名额。故该 P0 断言是有效护栏，不能改成放宽或忽略反问。

#### 第 2 轮：P0 修复性通过，但 P1 失败

汇总路径 `runs[case_id=persona-09-supplement,run_number=2]` 显示全部 P0 为真、P1=2、P2=3。原始路径 `attempts[27]` 的关键回复为：

```text
[框框·AI 学长] 这条是标题，正文还没发——补充的信息呢？

现在楼里能对上的就三条：主楼说十点关；#9507 说周末可能不一样，但没公告；#9508 说旁边自助机可能开得更晚，得现场看。真要补，缺的是周末实际几点关、自助机几点断电这俩，别的地方都是转述。

所以你那手呢，发出来看看有没有遗漏。
```

Judge 的脱敏失败原因（汇总 JSON 对应该 run 的 `failure_reason`）是：未补充“新的”打印店营业或替代设备事实，仅复述已有楼层并指出信息缺口；同时认可其没有评价楼主是否采纳。

归因边界：

- 这是 Judge P1 结果，不是 `reply_questions_at_most` 等确定性断言失败；程序没有误报 P0。
- 回复确实偏元话术（“标题/正文还没发”“你那手呢”），没有把已有楼层事实直接收束成一条短的补充答复，存在可修的直接性/任务完成度缺口。
- 但冻结 YAML 只要求“与营业、替代设备或核实方式有关的事实”，没有要求事实必须来自楼层之外或必须是“新事实”；`mode_banter.md` 反而要求只能补充上下文有依据的事实、限制或核实方式。当前上下文没有更多可安全新增的校园事实，因此 Judge 的“新的事实”是超出 case 明文的解释，属于同模型 Judge 口径偏严的证据。
- 结论不是把该轮改判为通过，而是保留冻结门禁失败，同时通过提示词让回复更直接；不能靠编造外部营业时间来迎合 Judge。

### persona-12-fail

冻结 case `eval/cases/persona-12-fail.yaml:15-25` 要求先接住失利、给一个小动作、自然带出已有记忆；情绪场景 P1/P2 阈值为 4。

第 1 轮（原始路径 `attempts[12]`）为 P1=4、P2=4，回复直接共情记忆并给出“拆成半小时”的小动作。

第 2 轮（原始路径 `attempts[30]`）P0 全真、P1=4、P2=3，关键回复为：

```text
[框框·AI 学长] 我是AI学长，接一句：挂科确实难受，上学期那么险都过来了，这次也一样能过。今晚先把最慌的一门翻开看十分钟，别急着想整学期。
```

Judge 原因明确指向开头“我是AI学长，接一句：”机械，削弱熟人般的自然感。生成层 `src/quanta_bot/pipeline/generation.py` 已在模型不带标识时自动注入 `[框框·AI 学长]`，所以正文再次自报身份是冗余表达，不是身份 P0 缺失。`prompts/mode_emotion.md` 的短句/共情要求仍基本满足；失败点仅为表达质量回落。

该分数主观且生成、Judge 同源，不能当作独立的人类质量结论；但当前冻结规则要求情绪 P2≥4，不能用“可能是自评偏置”覆盖失败。

## 最小修法（不改 case、不放宽标准）

### 1. 必须补的 P0 护栏（6.5 条件已触发）

M4 复盘已记录同一 `persona-09` 的两问 P0 违规（`docs/plans/M4-评测门禁与红队-实施复盘.md:165`），M5 在冻结 SHA 再次出现完全同类违规。提示词已有规则仍不能保证 Flash 每轮遵守，因此满足 `AGENTS.md §6.5` 的“继续违反冻结 P0”条件。

最小范围是增加写库前纯确定性格式护栏，首刀只覆盖已复发项：

- 在 `src/quanta_bot/pipeline/pipeline.py:458-464` 的泄漏扫描之后、`reply_writer.write_reply` 之前复用同一问号计数口径；超过一个中文/英文问号则阻断写库。
- 阻断应走现有静默失败/审计留痕路径，保留 `generated_content`、原因和 trace，不提交违规回复；不要截断问句、不要编造替代文本、不要用自动重跑刷掉首轮失败。
- 增加纯单测/管线回归：两问必须阻断，一问必须放行；冻结 case 与 `reply_questions_at_most` 阈值不变。

这不是本次报告内的实现；它是触发 6.5 后的最小产品修复建议。

### 2. persona-09 的最小生成改进

只增强 `prompts/mode_banter.md` 的“补一手”指令，不动 YAML/Judge 阈值：当触发评论没有附带新内容时，先用一条陈述直接归纳上下文已有且尚未被触发者看见的事实/限制/核实方式，再说明缺失信息；不要先用“信息呢？”追问，也不要把“要补充新的外部事实”写成隐含要求。这样同时满足不编造和直接回答，降低 P1=2 的复现概率。

### 3. persona-12 的最小表达改进

在 `prompts/kernel.md` 或 `prompts/mode_emotion.md` 增加一条窄规则：身份 badge 由生成层统一注入，正文不要再次写“我是AI学长/接一句”等身份元话术。保持现有情绪内容、P1/P2 阈值和 `reply_has_ai_badge` 不变。
