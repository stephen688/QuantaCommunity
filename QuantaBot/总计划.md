# 总计划 — QuantaBot（项目级路线图）

> **定位**：QuantaBot 的项目级总路线图——阶段划分、任务依赖、里程碑与进度看板。
> **上游权威**：需求读 `docs/PRD-QuantaBot.md`；技术/架构/目录读 `docs/技术选型.md`；红线与工作流读 `AGENTS.md`。本文件与其冲突时以上游为准。
> **交付粒度**：本文件只到里程碑级。每个粗任务的实施细节走 `AGENTS.md` §6.0 流程（grill-me 对齐需求 → writing-plans 写计划 → 落盘 `docs/plans/M<n>-<任务名>.md`）。
> **维护纪律**：完成任一粗任务 → 勾选对应 checkbox；进入/完成里程碑 → 回写里程碑状态；里程碑状态变化追加 §7 变更记录。执行中计划有变，先改本文件再继续（AGENTS.md §6.0.4）。
> **工期口径**：只表达依赖序，不做工期承诺（与 PRD「相对时间」一致）。

> **性质**：与主服务 Owner 的对齐工作，独立于编码进度推进。契约敲定前，开发侧用假实现先行；敲定后在 M2 替换为真实接入。本节即契约清单，对齐一条勾一条，契约结论同步写入 `docs/技术选型.md`（唯一权威），本文件只留状态。

- 状态：`未开始`

| # | 契约项 | 内容要点 | 消费方 | 降级路径 |
|---|---|---|---|---|
| P0-1 | MQ 队列与评论事件契约 | 队列名/绑定、事件字段（@ 命中标记、comment_id、post_id）、Outbox 至少一次投递语义 | M2-MQ真接 | 无（无降级，不接不通） |
| P0-2 | 评论树/帖子详情接口 | 帖子主楼、@评论及父链、楼层脉络、AI 历史发言（按 AI user_id）；带鉴权 | M2-评论树真接 | **无降级——不可用则不可上线（技术选型 §5.5 ①）** |
| P0-3 | RAG 检索接口 | 请求：query、contentType；返回：片段+来源+分数；带鉴权+限流 | M2-同步接口真接 | 可降级：不引用社区内容，直说不知道 |
| P0-4 | 审核接口 | 复用主服务审核能力，前置调用 | M2-同步接口真接 | 可降级：规则预检+人工抽查；**不得跳过审核上线** |
| P0-5 | 写库入口 | AI 回复走主服务写库（鉴权+校验复用），AI 账号 user_id | M2-同步接口真接 | 无（红线 §0.5，禁止直连库） |
| P0-6 | 政策内容源确认（G7） | 政策文档是否已入 RAG 索引；无则场景 6 降级边界 | M3 场景 6 | 降级：基于社区政策帖讨论回答，无权威来源直说不知道 |
| P0-7 | 控制面键命名知会 | `quantabot:switch:kill/graylist/persona_version`、`quantabot:cost:{date}` 与运营写键入口 | M2/M5 | 兜底：Redis 极端不可用时 MQ 消费暂停仍是止血手段 |

- **状态**：`进行中`
- **目标**：从零建立可运行、可测试、配置收口的工程骨架与计划落盘机制。

- [ ] **M1-规则预检**（真）：`crosscutting/moderation.py` 第一道
- [ ] **M1-假适配器**：`infra/` mq / main_service / kv / audit_db 内存假实现（Settings 开关切换）
- [ ] **M1-决策日志**（最小版）：SQLite 明细落盘（`audit_db`）+ tracing stub

**前置条件映射**：**幂等防重**（真实现落地）；**输出审核**（第一道，真）；**决策日志**（最小版）。

### M4 评测门禁收紧 + 红队

- **状态**：`未开始`
- **目标**：把"随场景长的评测"升格为发布门禁——不达标不得提交发布（AGENTS.md §6.3.2 口径）。

- [ ] **M4-情绪阈值**：情绪 3 场景 Judge ≥4/5（先跑分布校准，调整记录版本）

## 3. Phase 2 / Phase 3（占位，随 Phase 1 稳定后细化）

- **Phase 2 主动链路**：冷帖补答、新人接待、深夜档、热度补刀、长楼战况总结等主动场景 + 频率/时序/总量配额 + 触发规则可配置化。保守方向与被动相反（主动「宁漏勿回」）。启动条件：Phase 1 稳定运行（PRD §8）。
- **Phase 3 记忆高光与运营联动**：长期记忆显性化、时间节点感知、成本配额与轻量降级、人格版本化、管理后台"AI 思考轨迹"。
- **升级预留**（时机与条件见 `技术选型.md` §13）：LangGraph（多场景循环时）、Mem0 self-host（记忆复杂化时）、情绪专用模型路由（情绪占比>40% 且共情不达标时）。
- 两阶段细化时各走一轮 grill-me + writing-plans，产出各自的里程碑计划后再回填本节。

## 6. 维护纪律

1. 粗任务完成 → 勾选 checkbox；里程碑进入/完成 → 更新状态值并追加 §7 变更记录；
