# 发布页设计稿

> 对应实现：`miniprogram/pages/publish/index.*`。  
> 遵循 `design-system/校友社区/MASTER.md`，保持现有「内容类型 + 标题 + 正文 + 图片 + 提交」表单流程。

## 1. 页面目标

发布页是用户贡献内容的核心入口。视觉目标不是炫技，而是降低输入压力，明确生活/专业两种语境，并在提交前后给出可靠反馈。

## 2. 信息区块

1. **内容类型**
   - 现有：生活 / 专业 chip。
   - 职责：决定标题占位文案和内容语境。
   - 设计要求：两个 chip 要像「语境开关」，而不是普通按钮。

2. **标题**
   - 现有：单行输入 + `titleCount / 50`。
   - 职责：形成内容主题。
   - 设计要求：标题区域应更接近卡片表单，不出现强边框输入框。

3. **正文**
   - 现有：textarea，`maxlength=500`，auto-height。
   - 职责：承载内容细节。
   - 设计要求：正文区域需要足够安静的留白，帮助用户写长文本。

4. **图片上传**
   - 现有：`media-uploader`，最多 5 张，提交时 disabled。
   - 职责：补充生活图片或专业问题截图。
   - 设计要求：上传中、失败、禁用状态必须明显。

5. **提示 / 错误 / 提交**
   - 现有：tips、error、button。
   - 职责：发布前说明、错误反馈、最终提交。
   - 确认调整：底部增加固定提交操作栏，长内容填写时发布入口始终可见。
   - 设计要求：错误必须贴近提交区；提交按钮固定视觉权重最高。

## 3. 布局与栅格

- 页面 padding：`24rpx 24rpx 48rpx`，并额外增加底部留白 `calc(156rpx + env(safe-area-inset-bottom))`，避免固定提交栏遮挡内容。
- 分节卡片：白底，圆角 `16rpx`，padding `24rpx`，间距 `20rpx`。
- 表单字段：标题与输入之间 `16rpx`；计数器顶部 `12rpx`。
- 固定提交栏：固定在页面底部，左右 `0`，背景 `rgba(247,245,240,0.96)` 或 `--color-bg`，顶部边线 `1rpx solid var(--color-border)`。
- 提交按钮：栏内高度 `84rpx`，圆角 `999rpx`，左右边距 `24rpx`。
- 断点：小程序移动端优先，宽屏/平板不做双栏，保持最大阅读宽度自然随容器扩展。

## 4. 组件规格

### 分节卡片

- 背景：`--color-card-bg`。
- 圆角：`--radius-card`。
- Padding：`24rpx`。
- 建议边框：`1rpx solid --color-border`。
- 不使用大阴影；如果需要层级，只用 `--shadow-card`。

### Section Title

- 字号：`28rpx`。
- 字重：600。
- 颜色：`--color-text-primary`。
- 底部间距：`16rpx`。
- 可选：在「图片」标题右侧显示 `最多 5 张` 弱标签，但不新增功能。

### 内容类型 Chip

- 默认：背景 `#F0EDE7`，文字 `--color-text-secondary`。
- 激活生活：背景 `#F0EBE3`，文字 `#6B5B4F`，边框 `rgba(107,91,79,0.14)`。
- 激活专业：背景 `--color-brand-light`，文字 `--color-brand`，边框 `rgba(30,90,76,0.18)`。
- 尺寸：最小宽 `128rpx`，padding `14rpx 20rpx`。
- 禁用/提交中：整体 opacity `0.55`，不可切换。

### 标题输入

- 高度：`72rpx`。
- 字号：`30rpx`（可比正文略大）。
- 文本色：`--color-text-primary`。
- 占位：`--color-text-tertiary`。
- 计数：`22rpx`，右对齐，接近上限（≥45）时可用 `--color-warning`。

### 正文输入

- 最小高度：`260rpx` 保持。
- 字号：`28rpx`。
- 行高：1.6。
- 占位：`--color-text-tertiary`。
- 输入区不用重边框；通过分节卡片承载。

### 图片上传

- 上传格：建议使用 `148rpx` 正方形，圆角 `12rpx`。
- 空格背景：`#F0EDE7`。
- 上传中：骨架或半透明遮罩 + 小型 loading。
- 失败：边框/文案 `--color-danger`，提供重试/删除。
- 禁用：opacity `0.55`。

### 提交按钮

- 默认：背景 `--color-cta`，白字，`30rpx / 600`。
- 悬停/按下：opacity `0.9`。
- loading：保留小程序 `loading`，文案「发布中...」。
- disabled：背景 `#E8EBEF`，文字 `--color-text-disabled`。
- 错误：按钮上方 `error-text`，`--color-danger`。

### 固定提交操作栏（已确认纳入）

- 位置：`position: fixed; left: 0; right: 0; bottom: 0; z-index: 200`。
- 内边距：`16rpx 24rpx calc(16rpx + env(safe-area-inset-bottom))`。
- 背景：`rgba(247,245,240,0.96)`；若小程序兼容性不稳定，退化为 `--color-bg` 实色。
- 顶部分割线：`1rpx solid var(--color-border)`。
- 内容：错误摘要（如存在）在按钮上方，提示文案可收敛为一行；主按钮占满宽度。
- 键盘策略：输入聚焦键盘弹起时允许系统推动页面；若固定栏遮挡输入，需要在实现阶段根据微信表现增加 `scroll-into-view` 或临时隐藏栏。
- 禁用场景：`submitting || uploading` 时按钮 disabled；文案区显示「图片上传中，请稍候」或具体错误。

## 5. 色彩与语义

- 页面背景：`--color-bg`。
- 固定提交栏：`--color-bg` 半透明或实色，边线 `--color-border`。
- 主 CTA：`--color-cta`，不使用蓝紫渐变。
- 生活类型：暖灰/棕。
- 专业类型：浅绿/墨绿。
- 错误：`--color-danger`。
- 提示：`--color-text-secondary`。

## 6. 字体与图标

- 分节标题：`28rpx / 600`。
- 标题输入：`30rpx / 400`。
- 正文输入：`28rpx / 400`。
- 计数、提示、错误：`22-24rpx`。
- 上传图标：若组件使用图标，采用线性加号/图片框，不用 emoji。

## 7. 关键交互

- 切换内容类型：只清错误，不清已输入内容，现有逻辑正确。
- 输入标题/正文：实时更新计数，清错误。
- 图片变化：限制 5 张，上传中禁止提交。
- 提交校验顺序：标题 → 正文 → 图片数量 → 上传中 → 上传失败，现有逻辑正确。
- 固定提交：点击行为复用 `onSubmit`；滚动过程中保持按钮可见。
- 错误定位：提交校验失败后，固定栏显示摘要，同时可保留原 `error-text`；更进一步可滚动到对应字段，但不作为本轮默认要求。
- 提交成功：toast 后跳转详情；若无 contentId 则返回，现有逻辑可保留。
- 实名认证：后端提示转译为「请先完成实名认证」，需在 UI 中保持醒目但不恐吓。

## 8. 与现有实现衔接

1. **内容类型 chip 加边框与语义色**
   - 替换当前 `rgba(47,107,255,0.14)`。
   - 收益：生活/专业语境更明确，去电蓝。

2. **分节卡片增加细描边**
   - `.publish-card` 增加 `border: 1rpx solid var(--color-border)`。
   - 收益：白卡在暖灰底上更清晰。

3. **提交按钮改为纯墨绿**
   - `.submit-btn` 使用 `--color-cta`。
   - 收益：最关键 CTA 统一品牌。

4. **错误色 token 化**
   - `.error-text` 从 `#ff4d4f` 调整为 `--color-danger`。
   - 收益：与消息未读/失败语义统一。

5. **计数器临近上限反馈**
   - 可在后续实现 class，如 `count-text--warning`。
   - 收益：减少提交时才暴露的错误。

6. **提交按钮固定到底部**
   - 涉及：`publish-page` 底部 padding、提交按钮外层固定栏、错误提示位置。
   - 收益：长正文和图片上传场景下，发布动作始终可见。

## 9. 不纳入默认设计稿的大改建议

- 不改成多步骤发布流程。
- 不新增话题、位置、可见范围等功能。
- 提交按钮固定底部已确认纳入本轮；实现时需重点验证键盘、图片上传和安全区遮挡。
