# 消息页设计稿

> 对应实现：`miniprogram/pages/notification/index.*`。  
> TabBar 文案为「消息」，页面导航标题现为「通知中心」。保持现有通知列表结构。

## 1. 页面目标

消息页负责承接系统通知、互动通知与内容跳转。它需要让用户快速区分未读/已读、通知类型、正文摘要与发生时间，同时保持可信和克制。

## 2. 信息区块

1. **加载 / 错误 / 空状态**
   - 现有：`feed-skeleton variant="home"`、`state-block`、空状态「暂无通知」。
   - 设计要求：建议后续将 skeleton variant 改为 `notification` 或 `list`，避免首页卡片骨架错位。

2. **一键全部已读工具栏（已确认纳入）**
   - 位置：通知列表上方，与首条通知间距 `12-16rpx`。
   - 形式：轻量一行，右对齐文本按钮「全部已读」；或左侧弱说明 + 右侧操作，不抢列表主视觉。
   - 可用性：**仅当列表存在未读项时**可点；无未读、加载首屏中、列表为空时按钮 `disabled` 或隐藏（与产品择一，需全端一致）。
   - 职责：减少逐条消未读成本；成功后刷新列表并同步 TabBar 未读数（`setUnread` 等现有链路）。

3. **通知列表**
   - 现有：`nt__item card`。
   - 职责：展示通知类型、未读状态、正文、时间。
   - 设计要求：未读必须通过左边条 + 未读标签双重表达，不只依赖颜色。

4. **列表页脚**
   - 现有：`page-list-footer`，覆盖加载中、失败重试、已结束。
   - 设计要求：与首页/关注底部反馈统一。

5. **底部安全区**
   - 现有：`nt__safe-bottom`。
   - 设计要求：保留，避免被自定义 tabBar 遮挡。

## 3. 布局与栅格

- 页面 padding：`24rpx 24rpx 0` 保持。
- 工具栏行高：约 `64-72rpx`，与列表区之间可用 `1rpx` 弱分割或留白区分。
- 列表间距：`20rpx`。
- 通知卡 padding：`24rpx`。
- 类型与未读行：左右分布，垂直居中。
- 时间：正文下方 `12rpx`。
- 底部：`calc(120rpx + env(safe-area-inset-bottom))`。

## 4. 组件规格

### 通知卡

- 背景：`--color-card-bg`。
- 圆角：`--radius-card`。
- Padding：`24rpx`。
- 边框：`1rpx solid --color-border`。
- 阴影：默认无；若页面显得过平，可使用 `--shadow-card`。
- hover/按下：opacity `0.96`。

### 未读状态

- 左边条：`6rpx` 宽，颜色 `--color-unread` 或 `--color-brand`。
- 未读标签：高度约 `32rpx`，padding `0 12rpx`，圆角 `999rpx`。
- 未读标签色：背景 `rgba(196,61,61,0.10)`，文字 `--color-unread`。
- 已读：去掉左边条与标签，内容视觉不需要整体变灰过多，避免读不清。

### 类型与正文

- 类型：`28rpx / 600 / --color-text-primary`。
- 正文：`28rpx / 400 / --color-text-secondary`，行高 1.5，建议最多 3 行截断。
- 时间：`24rpx / --color-text-tertiary`。
- 如果 `typeDesc` 缺失，默认「通知」保持。

### 空状态

- 标题：`暂无通知`。
- 说明：`有新消息时会出现在这里`。
- 不需要主按钮，因为消息页没有明确创建动作。
- 图形：浅墨绿公告/信封抽象图形，禁止 emoji。

### 一键全部已读

- 文案：`全部已读`；处理中可为「处理中…」或直接按钮 `loading`，需防重复提交。
- 默认态：`26-28rpx`，`--color-text-secondary`。
- 可点：`--color-brand`；不可用：`--color-text-tertiary`，无下划线抢戏。
- 交互：可选二次确认或删除式撤销由产品裁定；至少具备请求中禁用、失败 toast、成功后列表与角标一并更新。
- 空数据：无通知时不展示该行，避免幽灵操作。

### 列表页脚

- 加载中：`--color-text-tertiary` + 小 loading。
- 加载失败：`--color-brand` 文本链接「加载失败，点此重试」。
- 已结束：`--color-text-tertiary`。

## 5. 色彩与语义

- 页面背景：`--color-bg`。
- 通知卡：`--color-card-bg`。
- 未读：优先 `--color-unread`，如果希望弱化紧张感，可将左边条改为 `--color-brand`、标签仍用 `--color-unread`。
- 类型：`--color-text-primary`。
- 正文：`--color-text-secondary`。
- 时间：`--color-text-tertiary`。

## 6. 字体与图标

- 不新增顶部标题，使用系统导航栏「通知中心」。
- 通知类型保持文字标签，不强行配图标。
- 若后续区分系统/互动/私信，可使用同一线性图标体系，不混用实心彩色图标。

## 7. 关键交互

- 下拉刷新：保留；刷新失败 toast。
- 触底加载：已有列表且未 finished 时触发。
- 一键全部已读：仅未读集合非空时可触发；成功后本地列表全部视为已读并刷新 TabBar 未读数。
- 点击通知：先标记已读，再刷新 tabBar unread，再根据 `payload` 跳转详情。
- `payload` 非 JSON 或缺字段时：仅标记已读，不跳转，现有逻辑合理。
- TabBar 未读：`setUnread` 上限 `99+`，保留。

## 8. 与现有实现衔接

1. **通知卡增加细描边**
   - `.nt__item` 或全局 `.card` 增加 `border`。
   - 收益：暖灰背景上层级更清楚。

2. **未读标签从纯文字改为胶囊**
   - `.nt__dot` 增加背景、padding、圆角。
   - 收益：未读状态更易扫读。

3. **未读左边条 token 化**
   - `.nt__item--unread` 使用 `--color-unread` 或 `--color-brand`。
   - 收益：统一状态色。

4. **列表 skeleton 改为通知列表形态**
   - 现在 `variant="home"`，建议新增/复用更接近列表的 variant。
   - 收益：加载状态与实际页面匹配。

5. **正文增加最大行数**
   - 对 `.nt__content` 加 3 行截断。
   - 收益：长通知不会打破列表节奏。

6. **列表顶部「全部已读」**
   - 涉及：`pages/notification` 模板增加工具栏、接口批量已读、`setUnread` 同步。
   - 收益：未读多时一键清理，和 TabBar 角标闭环。

## 9. 不纳入默认设计稿的大改建议

- 不新增消息分类 tabs（系统通知/互动/私信）。
- 一键全部已读已确认纳入本轮；不改变点击单条通知后的业务跳转策略。
