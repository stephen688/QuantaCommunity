# 校友社区 UI 设计稿交付总览

> 本目录用于指导 `demo0-miniprogram` 的 UI 美化落地。设计稿基于 UI-UX-Pro-Max 检索结果、当前小程序页面实现，以及「校友社区」的连接、归属、可信、校园记忆与轻社交语境整理。

## 1. 设计方向

整体视觉从当前偏通用 SaaS / 电蓝的风格，调整为「暖纸底 + 深墨绿 + 砖赭点缀」：

- **暖纸底**：承接校园公告栏、校友录、旧相册的温暖记忆。
- **深墨绿**：表达可信、成长、关系连接，替代泛 AI 产品常见电蓝。
- **砖赭点缀**：用于校友身份、审核中、轻量强调，避免高饱和娱乐社交感。
- **克制卡片**：白底、细描边、少阴影，避免模板化圆角卡片墙。
- **系统字体**：小程序端使用系统中文字体栈，不引入儿童感或英文字体。

## 2. UI-UX-Pro-Max 使用记录

已按要求先执行 `--design-system`，并补充 color、typography、ux 维度检索。最终没有机械照搬检索结果，而是取其「Community/Forum」「暖色欢迎」「活动绿」「空状态引导」「150-300ms 动效」「反模式规避」等原则，结合当前小程序重新落地。

详细记录见：

- `MASTER.md`：全局设计系统、token、组件状态、Pro-Max 取舍说明。

## 5. 统一验收标准

- 色彩不再依赖泛 AI 蓝色或蓝紫渐变，主色使用 `#1E5A4C`。
- 每个页面保留当前功能和大致信息架构，不引入未经确认的新功能。
- 主要组件覆盖默认、触摸/按下、禁用、加载、错误、空状态。
- 空状态不留白，至少包含标题、说明；有明确后续动作时提供单一 CTA。
- 未读、错误、认证状态不只靠颜色表达，应有文案或形态辅助。
- 列表底部保留 tabBar 安全区，不遮挡内容。
- 图标不用 emoji，不混用多套风格。
- 动效控制在 150-300ms，避免 scale 造成布局跳动。

## 6. 推荐落地顺序

先做全局 token 和 TabBar，再做共享组件，最后逐页微调。这样能用最小改动获得最大统一性。

详见 `implementation-priority.md`。
